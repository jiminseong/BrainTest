# 올리기 (PR 만들기)

이 저장소는 사이트 주인이 PR을 머지해야 실제 사이트에 반영됩니다. 에이전트는 PR까지만 만듭니다.

1. 현재 브랜치를 확인합니다. `main`이나 `develop`이면 멈추고, 변경 내용을 새 브랜치(`edit/MMDD-내용`)로 옮긴 뒤 진행합니다.
2. `npm run build`가 통과하는지 다시 확인합니다. 실패하면 PR을 만들지 않고 원인을 설명합니다.
3. 변경된 파일을 확인하고, 요청과 무관한 파일이 섞여 있으면 사용자에게 알리고 제외합니다. `_meeting/`, `.env*`, `node_modules`, `dist`는 절대 포함하지 않습니다.
4. 커밋합니다. 메시지는 한국어 한 줄, 무엇을 바꿨는지만 적습니다. 예: `문항 17번 문구 수정`, `유형 5 뉴런 이미지 교체`
5. 푸시하고 `develop`을 대상으로 PR을 만듭니다.
   ```
   git push -u origin <브랜치>
   gh pr create --base develop --title "<커밋 메시지와 같은 한 줄>" --body "<무엇을 왜 바꿨는지 두세 문장>"
   ```
   `gh`가 로그인돼 있지 않으면(`gh auth status` 실패) `gh auth login`을 안내합니다. 브라우저에서 GitHub 로그인 한 번이면 됩니다.
6. 만들어진 **PR 링크를 사용자에게 보여주고**, "이 링크를 사이트 주인에게 보내면 확인 후 반영됩니다"라고 안내합니다.
7. PR 화면에서 Vercel 검사가 실패로 보여도 무료 플랜 제약 때문이며 수정 내용의 문제가 아니라고 미리 알려줍니다.
